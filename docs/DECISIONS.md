# Decision log

- 2026-08-11 — The Azure deployment is promoted by blue-green migration to one production environment, `rg-skillmap-prod`, with `skillmap-prod-*` resource names. This is a parallel replacement because Azure resource names cannot generally be renamed; it is not a second long-lived environment. Central India, PostgreSQL `Standard_B1ms`/32 GB, one warm 0.5-vCPU/1-GiB Container App replica, private networking, managed identity, private Blob Storage, Key Vault references, ACR Basic, ACS Email, and the scheduled job remain unchanged architecturally. Future releases use Container Apps multiple-revision mode: candidate revisions receive zero traffic until healthy, then traffic is promoted with rollback protection and the superseded revision is deactivated. The PostgreSQL 16 dump/restore reconciled all 15 application-table counts exactly (1 leader, 167 skills, 1 audit log, all other application tables zero); certificate storage reconciled at 0 blobs/0 bytes. Revision `skillmap-prod-web--cutover-59a000a` serves the production verification hostname and passes application/database health, migration, sign-in-route, provider-metadata, and protected-route checks. Interactive Entra role, full wizard, image/PDF, and signed-URL verification remains the cutover gate; therefore the old redirect and all `skillmap-dev-*` resources are intentionally retained for a later, explicitly approved decommission after a stability window. The custom domain is a follow-up and was not bound during this migration.

- 2026-08-11 — The Capability Map and Career Aspiration enhancements ship as one development-environment batch. The Overview reference table is generated from the same `data/capability-mapping.json` configuration as the Capability Matrix, keeping all ten capabilities, fourteen categories, display labels, and assignment rules in one source of truth. It opens for users without profile skills and remains collapsible for returning users. Career Journey is replaced by structured Career Aspiration so future quarterly KPI handover can compare canonical current skills with explicit 1–5 target proficiency instead of interpreting narrative text. The portal remains decoupled from QuikITScale and exposes read-only handover views for later use. The migration preserves every non-empty legacy journey in `CareerAspiration.legacyJourneyBackup` before dropping `Leader.careerJourneyRaw`; pre-deployment inspection of `skillmap-dev-web` found zero non-empty legacy journeys and zero old target-proficiency values to migrate. Release `59a000a` (`capability-map-and-aspiration-stable`) was deployed only to the current development Container App as revision `skillmap-dev-web--0000011`, serving 100% of development traffic with one warm replica. All eight migrations are applied, the database-backed health endpoint and sign-in route pass, and the production cutover remains a separate follow-up.

- 2026-08-11 — The approved profile-wizard enhancement batch standardizes Basic Info departments to the ten agreed operating groups; replaces project prose with repeatable name, description, and HR-taxonomy tech-stack records; opens each skill row on an unselected taxonomy combobox and removes the duplicate Tools section; and stores repeatable certification evidence in private Azure Blob Storage with image and PDF support. This is the final profile data-entry contract for this release and supersedes the earlier free-text department, project, skill/tool, and certification controls. The added `Standard_LRS` Hot blob account is a low-cost, usage-based part of the already-approved Azure footprint at the anticipated small certificate volume. Release `51760f5` (`profile-wizard-enhancements-stable`) was deployed to Azure Container Apps revision `skillmap-dev-web--0000010` in Central India with one warm replica; the private `certifications` container and managed-identity role assignment were provisioned, both new production migrations completed, and the live application/database health check passed.

- 2026-08-11 — Certification evidence is stored in a private Azure Blob Storage container, never in PostgreSQL or the Container App filesystem. PostgreSQL stores only the blob name, content type, original-safe filename, and byte count. The user-assigned Container App identity has Storage Blob Data Contributor at storage-account scope so it can upload/delete files and mint short-lived, read-only user-delegation SAS URLs after application authorization. JPEG/PNG/WebP uploads are metadata-stripped, resized, and converted to WebP; PDFs are signature- and size-validated and stored byte-for-byte. This supersedes the uncommitted database-binary prototype.

- 2026-08-10 — Dashboard review found that only the recent-leader cards used the database; the date, greeting, completion percentage, review count, canonical category count, capability list and percentages, quarterly growth, and weekly insight were hardcoded prototype values. The dashboard now uses one live database aggregation path: canonical skill count, category count, review flags, and coverage share the same `Skill` rows; coverage de-duplicates leaders across rating sources; quarterly growth uses `KpiSnapshot` history and reports a clear no-history state instead of invented growth. Date and greeting are computed in the browser's local time zone. The apparent Admin/Leader conflict was caused by lowercasing the Entra-derived access role in the account panel while the profile card used a hardcoded “Leader” fallback for a missing job title; both now show the actual access role in title case, with job title presented separately when available.
- 2026-08-10 — Microsoft Entra security groups are the authoritative application RBAC source: `Skillmap Administrators` (`1353375d-4bbc-45a7-aa31-fac6d3b0564e`) resolves to `ADMIN`, `Skillmap Leaders` (`9879fb2d-d8aa-47cc-849f-4bc6ec07096f`) resolves to `LEADER`, Admin wins if both claims are present, and absence of both fails closed to `VIEWER`. The Entra app emits security-group claims and the same IDs are set in both the ARM deployment parameters and Container App environment. Review found that the earlier callback allowed an existing database role to override a Leader claim or survive group removal; sign-in now derives the token role only from Entra groups and synchronizes the database role to that result.
- 2026-08-10 — The HR-provided `data/tech-skills-taxonomy.json` is now the authoritative skill/tool selection source, superseding wizard free-text entry. It contains 13 categories and 157 listed entries representing 155 unique canonical names; `Power BI` and `Microsoft Fabric` occur twice, so their first-listed category wins under the existing globally unique `Skill.name` model. The wizard accepts only taxonomy selections and routes “Other (specify)” skill/tool requests to the pending review queue without creating canonical rows. Legacy and AI ingestion resolves exact HR terms first, then approved normalization aliases/`SkillAlias`, then conservative fuzzy matches; unresolved terms require human review rather than silently extending the taxonomy.
